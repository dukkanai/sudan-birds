# Supplemental SDK lifetime and timed-gate evidence, 2026-11-09

This supplements the historical bundle/SDK experiments; it does not replace or
relabel them. Production base is `b99b53b9da51b2dbf534afb4e915a0bf830cedc5`
plus the exact uncommitted, independently reviewed source hashes below. This is
ordinary local Deno 2.5.6 evidence, not Supabase isolate capacity, actual socket
closure, live R2 integration or release approval.

No hosted request, real credential, account, object, role, scheduler, deployment,
upload enablement, cloud deletion, commit or push was performed. Changes for this
supplement are confined to `scripts/media_sdk_*` and this new report. Historical
measured JSON was preserved byte-for-byte; its hashes appear below.

## Correspondence reviewed before repinning

The earlier launcher correctly rejected the changed R2 and image-stream sources.
It was not bypassed. After production freeze and independent review, the local
fixture was reconciled before accepting new pins:

- Fresh operation-owned clients now **destroy by default in finally**, including
  signing errors, stream failures, cancellation and PUT/HEAD failures. A download
  owner remains alive through consumption or bounded cancellation; one fence owner
  remains alive through both commands and final metadata verification.
- Metadata mismatch now calls the actual production `cancelImageStream` helper,
  rather than direct unbounded `stream.cancel`. The actual production
  `readExactImageStream` also covers body consumption, overflow and abort.
- Canonical writing now matches the frozen finite initial TTL check, full signed
  TTL versus fresh absolute deadline recheck after signing, and remaining-time
  AbortSignal timeout. No signed PUT is dispatched on a rejected deadline.
- S3 factory options, command inputs, signing contracts and installed dependencies
  remain unchanged. The presign and package-lock pins are unchanged. Current
  `media/handler.ts` and `media_trial.ts` were added to the launcher pins so a gate
  change cannot silently leave these measurements apparently current.
- The actual current media handler uses one fixed, two-synthetic-ID, 20-minute
  local trial window per process. It is not renewed per request, persisted or
  written to any real environment. Auth/RPC still use closed synthetic transport.
- The only no-destroy option is named `counterfactualNoDestroy` and the scenario
  `counterfactual-no-destroy`. It is not a current-source baseline and was **not
  run as a resource scenario** in this supplement. One unit test checks the
  explicitly counterfactual option; old data retains its old source attribution.

An independent scoped review found no remaining correspondence blocker for the
frozen fixture/driver/tests. Its production review separately passed 149 Edge
tests. This supplement's own strict suite passed **15 SDK tests**, including seven
new cleanup/ordering/deadline cases, and **3 launcher tests**, including the
positive six-pin match and mutation rejection for every pin. Formatting, lint,
type checking, shell syntax and whitespace checks passed. Final-commit CI remains
separate from these local results.

## Bounded local execution

The same fixed synthetic 640×640 JPEG is used: 571,931 input bytes and 571,691
canonical output bytes. The native Deno binary/cache and denied permissions match
the prior SDK experiment. The launcher clears inherited environment data and uses
only inert SDK metadata configuration plus synthetic non-credentials. Runtime
network, file reads/writes, subprocess, sys and FFI permissions are denied and
asserted; modules come from the prepared local tree/cache. No listener is started.
Reports contain no signed URL, signature, credential literal or request body.

Bounds remain 64 handler requests, 128 clients, 128 SDK attempts, 1,024 stream
chunks and 768 memory samples per process, a checked 90-second deadline and a
120-second external process timeout. There is no forced GC, V8 tuning, threshold
increase, hosted probe, or unsupported worker API.

Exactly five new processes ran: three paced sequences, one burst and one boundary
run. Total: **90 handler requests**. Each paced sequence used 100-ms inter-request
gaps, 5-ms closed transport waits, 20 requests, then two seconds idle and one
recovery request. Supplemental read signing and orphan fencing followed successful
completions; these are separate synthetic workloads, never removal of a published
winner. All three initial sequences were 20/20 and all three recovery calls were
200. Each constructed and destroyed 84 clients and consumed 21 image streams.

## Boundary outcomes and limits

All 18 boundary requests matched their expected outcomes, plus a separate failed
fence-metadata check. The raw results below preserve every expected 400/409/429/
500/502/503 rather than treating negative responses as successful operations.

- Wrong metadata/overflow returns 400 and cancels; truncated bytes return 400.
  Missing SDK body still becomes safe 500 before the adapter's body guard.
  AccessDenied is not retried; one SlowDown response is retried once.
- The stalled SDK response-body timeout returned 502 after 15010.56
  ms and canceled its stream. Signed conflicts/failures return 409/502 without
  commit; admission denials produce no write/commit.
- A deliberately never-settling metadata cancellation returned 400 after
  1005.37 ms. Its owner was destroyed after the one-second grace,
  with cancellation still pending. This is the intended bound on waiting, **not
  proof that cancellation or transport closure finished**. Unit tests also
  verify delayed settlement before destruction, rejected cancellation preserving
  the original error, overflow grace, held final HEAD and separate concurrent
  download ownership.
- Expired/unlisted trial requests return 503 before prepare/client construction.
  Revocation during download returns 503 after consuming the stream and
  destroying its owner, without a canonical write or commit.
- Synthetic clock advancement during signing returns 409 `upload_expired` before
  signed PUT/commit, with all created clients destroyed. This checks the local
  gate/adapter control flow. The clock override does not change the SDK's own
  signing Date, so it is **not additional proof of actual signed absolute expiry**;
  the separately reviewed production tests cover their actual asynchronous
  signing/deadline behavior.
- The final recovery succeeds. The boundary run created/destroyed 21 clients,
  canceled five streams, and observed four cancellation settlements plus the one
  intentionally pending cancellation above.

Independent SigV4 recomputation still adds simulated server-side WebCrypto work
and allocations inside this process. These results do not isolate SDK allocation
cost or bound production memory. The local requestHandler owns no real sockets;
`destroy` instrumentation proves delegation/order only, not a fixed leak or actual
socket closure. A Node underlying `_destroy` callback may outlive cancellation
promise settlement and client destruction; this supplement does not strengthen
that guarantee.

The closed signed PUT checks its signal after synthetic delay, then performs
asynchronous HMAC verification and metadata mutation. It does not reproduce
production fetch's timeout/abort/redirect semantics. Actual R2 signature
acceptance, transport/socket behavior, create-only/tombstone durability and races,
Supabase isolate CPU/memory/reuse, live Auth/RLS and device behavior remain open
gates. Uploads and thresholds must not be changed based on this report alone.

## Reproduction

From the repository root with prepared dependencies and the reviewed source pins:

```sh
export DENO_BIN=/absolute/path/to/native-deno-2.5.6
export DENO_DIR=/absolute/path/to/prepared-deno-cache
for repeat in 1 2 3; do
  bash scripts/media_sdk_resource.sh --run-local sequential-paced
done
bash scripts/media_sdk_resource.sh --run-local burst
bash scripts/media_sdk_resource.sh --run-local boundaries
python3 -m unittest discover -s scripts -p media_sdk_launcher_test.py
```

The strict Deno unit-test command uses the launcher's same cleared environment,
SDK metadata allowlist, cached-only/no-remote/no-lock flags and all six denied
permission categories, but invokes `deno test scripts/media_sdk_resource_test.ts`
instead of a resource scenario. It does not require hosted access.
